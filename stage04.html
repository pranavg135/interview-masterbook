02

Python Fundamentals

Data types, data structures, control flow, functions, error handling, files/modules, OOP, and the iterator/generator pattern.

Variables & Data Types A

Python is dynamically typed — a variable's type is inferred at runtime and can change. Core types: int, float, str, bool, and None.

Worked example
x = 5 # int x = x / 2 # now a float: 2.5 print(type(x)) # <class 'float'> print(0.1 + 0.2 == 0.3) # False — floating point precision
0.1 + 0.2 actually equals 0.30000000000000004 in binary floating point — a classic gotcha behind "why doesn't my equality check work" bugs.
Interview"Why compare floats with math.isclose() instead of ==?" — binary floating point can't represent most decimals exactly.
Your CVCost-per-call thresholds at Axtria are exactly the kind of float comparison this bites.

Lists, Tuples, Sets, Dictionaries A

List: ordered, mutable. Tuple: ordered, immutable (hashable, usable as dict keys). Set: unordered, unique elements, O(1) membership check. Dict: key-value pairs, O(1) average lookup.

Worked example
reps = ["Meera", "Karan", "Meera"] unique_reps = set(reps) # {'Meera', 'Karan'} rep_scores = {"Meera": 92, "Karan": 87} print(rep_scores.get("Divya", 0)) # 0 — safe default, no KeyError
.get() with a default avoids a KeyError for a missing key — the safe pattern vs. rep_scores["Divya"], which would crash.
Interview"Why use a set to dedupe instead of a list + loop?" — O(1) average membership check vs. O(n) scanning a list each time.
Your CVDeduplicating client names across NanoCloud exports is exactly a set/dict use case.

Loops & Comprehensions A

List/dict/set comprehensions build a new collection in one readable line — generally preferred over an explicit loop + .append() for simple transformations.

Worked example
durations = [4, 12, 6, 25, 3] long_calls = [d for d in durations if d > 10] print(long_calls) # [12, 25] efficiency = {r: s/100 for r, s in rep_scores.items()} print(efficiency) # {'Meera': 0.92, 'Karan': 0.87}
Interview"When would you NOT use a comprehension?" — when the logic is complex enough that readability suffers; a regular loop is clearer at that point.

Functions, *args/**kwargs & Lambda A

*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict. lambda defines a small anonymous function inline.

Worked example
def score(base, *bonuses, **flags): total = base + sum(bonuses) if flags.get("penalize"): total -= 5 return total print(score(80, 5, 3, penalize=True)) # 83 reps_sorted = sorted(rep_scores.items(), key=lambda x: x[1], reverse=True)
Your CVThe rep-scoring function behind Axtria's allocation model would naturally take this shape.

Exception Handling A

try/except/else/finally — catch specific exception types (never a bare except:), and use finally for cleanup that must always run.

Worked example
def safe_divide(a, b): try: return a / b except ZeroDivisionError: return None finally: print("attempted division") print(safe_divide(10, 0)) # prints "attempted division", returns None
Interview trapA bare `except:` silently swallows ALL errors, including ones you didn't anticipate (like a typo) — always catch specific exception types.

File Handling & Modules B

The `with` statement (context manager) guarantees a file gets closed even if an error occurs mid-read — always preferred over manual open()/close().

Worked example
with open("call_log.csv") as f: header = f.readline() # file is automatically closed here, even if an exception happened above

OOP / Classes B

__init__ sets up instance state; methods define behavior; inheritance lets a subclass reuse and extend a parent class's behavior.

Worked example
class Rep: def __init__(self, name, region): self.name = name self.region = region self.calls = [] def log_call(self, duration): self.calls.append(duration) @property def avg_duration(self): return sum(self.calls) / len(self.calls) if self.calls else 0 m = Rep("Meera", "West") m.log_call(5); m.log_call(7) print(m.avg_duration) # 6.0
Your CVModeling each rep as an object with call history is a natural OOP structure behind an efficiency-scoring pipeline.

Iterators & Generators B

A generator (using `yield`) produces values lazily, one at a time, instead of building the whole list in memory — critical for large datasets.

Worked example
def call_batches(calls, batch_size=1000): for i in range(0, len(calls), batch_size): yield calls[i:i+batch_size] # processes one batch at a time; never holds all batches in memory simultaneously
Interview"Why use a generator instead of returning a full list?" — memory efficiency on large datasets; values are produced on demand, not all at once.
Your CVProcessing Axtria's full call history in batches rather than loading everything into memory at once.
03

NumPy

The array library everything in Pandas and scikit-learn is built on top of.

Arrays & Vectorization A

A NumPy array is a fixed-type, contiguous block of memory — operations run in compiled C, not the Python interpreter loop, which is why vectorized NumPy code is dramatically faster than an equivalent Python for-loop.

Worked example
import numpy as np durations = np.array([4, 12, 6, 25, 3]) efficiency = durations / durations.max() # vectorized, no loop print(efficiency) # [0.16 0.48 0.24 1. 0.12]
Every element divided by the max in one vectorized operation — no explicit Python loop, and much faster at scale.
Interview"Why is NumPy faster than a Python list loop?" — vectorized operations run in compiled C under the hood, avoiding Python's per-element interpreter overhead.

Broadcasting, Indexing & Boolean Masking B

Broadcasting lets NumPy apply an operation between arrays of different (but compatible) shapes without explicit loops. Boolean masks filter arrays using a condition.

Worked example
mask = durations > 10 print(durations[mask]) # [12 25] print(durations.mean(), durations.std()) # 10.0, 8.09...
Your CVFlagging outlier calls at Axtria for review is exactly a boolean-mask filter.
04

Pandas

DataFrames, filtering, groupby, merging, reshaping, cleaning, and datetime/string handling — the actual daily toolkit.

DataFrames & Series A

A DataFrame is a 2D labeled table; a Series is a single labeled column. `.loc` selects by label, `.iloc` selects by integer position — mixing them up is a classic bug.

Worked example
import pandas as pd df = pd.DataFrame({ "rep": ["Meera","Karan","Divya"], "region": ["West","West","East"], "calls": [42, 38, 51] }) print(df.loc[df.rep=="Meera", "calls"]) # label-based: 42 print(df.iloc[0, 2]) # position-based: 42
Interview trap.iloc[0] after filtering doesn't mean "the first matching row" — it means literal position 0, which may not exist post-filter. Use .loc or reset_index() instead.

Filtering & Selection A

Boolean masks, `.query()`, and chained conditions with `&`/`|` (not `and`/`or`, which don't work element-wise on Series).

Worked example
west_high = df[(df.region=="West") & (df.calls > 40)] # equivalent: df.query("region=='West' and calls>40")
Interview trapUsing `and`/`or` instead of `&`/`|` between two boolean Series raises "ambiguous truth value" — Python's and/or aren't overloadable element-wise.

GroupBy & Aggregation A

Split-apply-combine: split into groups, apply a function to each, combine results — Pandas' equivalent of SQL's GROUP BY.

Worked example
summary = df.groupby("region").agg( total_calls=("calls","sum"), avg_calls=("calls","mean"), num_reps=("rep","count") ).reset_index() print(summary) # region total_calls avg_calls num_reps # East 51 51.0 1 # West 80 40.0 2
Your CVThe per-region rep-efficiency summary behind the Axtria allocation decision is exactly this groupby.

Merge, Join & Concat A

`merge()` mirrors SQL joins (how='inner'/'left'/'right'/'outer'); `concat()` stacks DataFrames along an axis (rows or columns), like SQL's UNION.

Worked example
orders = pd.DataFrame({"rep":["Meera","Karan"], "revenue":[12000, 9500]}) merged = df.merge(orders, on="rep", how="left") # Divya (no orders) keeps her row with revenue=NaN, exactly like SQL's LEFT JOIN
Interview trapmerge() can silently multiply rows on a one-to-many key, just like a SQL join — always check `df.shape` before/after.

Pivot & Melt B

`pivot_table()` reshapes long data into wide (rows→columns); `melt()` does the reverse, wide into long.

Worked example
pivoted = df.pivot_table(index="region", values="calls", aggfunc="sum") long_form = pivoted.reset_index().melt(id_vars="region", var_name="metric", value_name="value")

Apply, Map & Transform B

`.map()` — element-wise on a Series. `.apply()` — row/column-wise on a DataFrame, or element-wise on a Series with custom logic. `.transform()` — like apply but returns an object of the same shape, useful for broadcasting a groupby result back onto every row.

Worked example
df["region_avg_calls"] = df.groupby("region")["calls"].transform("mean") # every row gets its region's average, aligned back to the original shape — no merge needed
Interview"When would you use transform instead of a groupby+merge?" — when you need the group aggregate broadcast back to every original row, without a separate join step.

Missing Values & Duplicates A

`.isna()`/`.fillna()`/`.dropna()` for missing data; `.duplicated()`/`.drop_duplicates()` for exact or partial-key duplicates.

Worked example
df["revenue"] = df["revenue"].fillna(0) clean = df.drop_duplicates(subset=["rep"], keep="last")
Interview trapfillna(0) is only correct if 0 is a meaningful default — filling a missing revenue with 0 could badly bias an average; sometimes dropping or flagging is more honest.

Datetime & String Operations A

`pd.to_datetime()` parses dates; the `.dt` accessor extracts components. `.str` accessor applies vectorized string operations across a Series.

Worked example
df["call_date"] = pd.to_datetime(df["call_date"]) df["month"] = df["call_date"].dt.to_period("M") df["rep_clean"] = df["rep"].str.strip().str.title()

Performance B

Vectorized operations (built-in Pandas/NumPy methods) are almost always faster than `.apply()` with a Python function, which is faster than an explicit `for` loop over rows — in that order.

Worked example
# Slow: row-by-row Python loop for i, row in df.iterrows(): df.loc[i, "flag"] = row["calls"] > 40 # Fast: vectorized df["flag"] = df["calls"] > 40
Same result, but the vectorized version can be 10-100x faster on a large DataFrame, since it avoids the per-row Python overhead of iterrows().
Interview"Your Pandas pipeline is slow on 10M rows — first thing you'd check?" — any .iterrows()/.apply() that could be rewritten as a vectorized operation.

Visualization

Matplotlib B

The foundational plotting library — lower-level, more manual control, and what most other Python viz libraries (including Seaborn) render through underneath.

Worked example
import matplotlib.pyplot as plt df.groupby("region")["calls"].sum().plot(kind="bar") plt.ylabel("Total Calls") plt.title("Calls by Region") plt.show()

Seaborn C

Built on Matplotlib, with better defaults for statistical plots (distributions, categorical comparisons) and native Pandas DataFrame support.

Worked example
import seaborn as sns sns.boxplot(data=df, x="region", y="calls") # one line to see the full distribution + outliers per region, not just the mean
Your CVA boxplot of call durations per rep is a natural exploratory step before building the Axtria efficiency model.

Red Flags

"I looped over rows with .iterrows() because it was easier to read." — Fine for a one-off 50-row script; a real production concern on anything large. Always ask if it vectorizes.
"I used a bare except: to catch everything." — Silently hides real bugs (typos, wrong types) alongside the error you meant to catch.
"merge() gave me more rows than expected, so I just deduped after." — Deduping after the fact can hide which rows were wrong; check for the row-multiplication cause first.
"I filled all my NaNs with 0 to make it work." — Only valid if 0 is a real, meaningful default for that column — otherwise it silently biases every downstream aggregate.
